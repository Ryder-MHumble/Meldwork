# Meldwork 品牌策略

> 日期：2026-07-31
>
> 状态：工作名称与候选视觉，待商标、域名和用户理解测试后确认

## 1. 品牌核心

### 品牌角色

Meldwork 不是制造 Agent 的公司，也不是把十个 Agent 头像放进一个群聊的工具。

它的角色是：

> **让不同 Agent 接续同一份真实工作，并让用户始终看得见任务、边界、证据和结果。**

### 品牌关键词

- Open：开放连接，不绑定单一模型或厂商。
- Local-first：控制面和工作记录默认在本机。
- Accountable：工作可追溯、可比较、可验收。
- Cross-vendor：全球与中国 Agent 平等接入。
- Quiet confidence：专业、克制、不用“AI 魔法”语言。

### 品牌应避免

- 网络节点、蜂巢、中心控制器等工业化多 Agent 图形。
- 对称的三路汇聚、机器人和拟人团队隐喻。
- 蓝紫渐变、发光 Orb 和通用 AI Spark。
- “无限自治”“AI 团队自动完成一切”的夸张承诺。
- 把 local-first 暗示为完全离线。

## 2. 命名判断

### 推荐继续使用 Meldwork

下表是基于当前定位的启发式评估，不是用户研究结果。各维度尚未加权，也没有经过目标市场样本测试。

| 维度 | Meldwork | MAC-Work | Open-MACWork | RoundRelay |
| --- | ---: | ---: | ---: | ---: |
| 全球可读可念 | 4/5 | 3/5 | 2/5 | 4/5 |
| 与产品价值关联 | 4/5 | 3/5 | 3/5 | 3/5 |
| 可扩展到 Cloud/Channel | 5/5 | 3/5 | 3/5 | 3/5 |
| 品牌辨识度 | 4/5 | 2/5 | 2/5 | 3/5 |
| 歧义风险 | 4/5 | 1/5 | 1/5 | 3/5 |
| 总体建议 | 推荐 | 不推荐 | 不推荐 | 不回退 |

### 为什么不推荐 MAC-Work / Open-MACWork

- `MAC` 容易被理解为 Apple Mac、MAC address 或 Mandatory Access Control。
- 用户给出的英文展开中 `Muti-Agent` 应为 `Multi-Agent`。
- `Open Resource Multi-Agent Collaborative Work` 像为缩写反向拼接的句子，不自然，也很难成为国际品牌叙事。
- 名称把产品锁定在“multi-agent collaboration”功能，而 Meldwork 可以扩展到 Cloud Agent、Channel、Workflow 和治理。

### 为什么 Meldwork 更合适

- `Meld` 表示接续并把分散工作状态带入同一可审查记录，不意味着答案必须融合或一致。
- `work` 明确产品服务真实工作，而非泛聊天。
- 名称不强制解释 Agent 数量，能覆盖未来的 Task、Artifact、Evidence 和 Channel。
- 读音简单，视觉上适合形成 `m` 的独立标志。

### 五个备选名

| 名称 | 逻辑 | 优点 | 主要风险 |
| --- | --- | --- | --- |
| Meldwork | 接续不同 Agent 的工作 | 最符合当前品牌资产与长期扩展 | 需要品类描述帮助首次理解，并防止被误解为强制融合 |
| Commonline | 多 Agent 进入共同工作线 | 与连续线 Logo 关联强 | 通用词较多，商标/域名风险需查 |
| Relaycraft | 接力 + 专业工作 | 有动作感，延续 RoundRelay 部分资产 | 偏“接力”，弱化治理与证据 |
| Workloom | 不同线索织成工作成果 | 视觉隐喻丰富、非工业化 | `loom` 在 AI 产品中使用较多 |
| Threadbase | 持续工作线与上下文基础 | 产品化、适合 Channel | 容易被理解为消息 Thread 数据库 |

**当前建议：把 Meldwork 作为工作名称继续推进，不再在开发阶段频繁切换主品牌。** 只有在目标市场商标、核心域名或英语/中文理解测试出现实质障碍时再改名。

国内首次传播不强造音译品牌名，使用 `Meldwork（跨厂商 Agent 工作系统）`；读音统一为 `meld-work`。是否采用“联作”等中文副品牌，必须经过中国目标用户的记忆与复述测试后再决定。

### 名称风险说明

截至 2026-07-30 的当次实抓检查：npm 没有完全同名 package；GitHub 仓库名搜索只有 `meldworks` 等近似结果；[`meldwork.com` 的 Verisign RDAP](https://rdap.verisign.com/com/v1/domain/meldwork.com) 显示其已于 2024-12-20 注册，当前注册期到 2026-12-20，并非可直接使用的主域名；[`meldwork.ai`](https://rdap.org/domain/meldwork.ai) 与 [`meldwork.dev`](https://rdap.org/domain/meldwork.dev) 的 RDAP 查询当前无注册记录，但这不等于注册一定可用。开发者也可能把 `meld` 联想到既有的 Meld diff/merge 工具，因此需要在 5 秒理解测试中记录这种联想。公开发布前仍需完成美国、中国、欧盟目标市场第 9/42 类及近似图形的正式商标检索、域名下单核验和社交账号占用检查。

## 3. 信息架构

品牌传播使用三层，不让一个 Slogan 承担全部解释责任。当前 MVP 与目标 Harness 使用阶段化文案，避免把 Evidence/Acceptance 路线图写成已实现能力。

### 第一层 A：当前 MVP Slogan

> **Agents change. Work continues.**
>
> **Agent 可切换，工作不断线。**

当前 README 和 MVP 演示优先使用这条文案，因为它与持久会话、兼容 Session 延续和跨 Agent 工作空间的已实现价值一致。

### 第一层 B：目标产品 Slogan

> **Different agents. Work you can verify.**
>
> **不同 Agent，工作有据可验。**

作用：在 Task、Artifact、Evidence 和 Acceptance 形成真实产品闭环后，把品牌记忆落在跨厂商差异、独立观点和可验证工作，而不是 Agent 数量、角色扮演或强制共识。

不再把 `Many agents. One shared outcome.` 作为首选：名称 `Meldwork`、单条连续线和 `shared outcome` 同时出现时，容易让人误解为顺序群聊、答案融合或强制共识。`Different agents. Work you can verify.` 更直接表达异构 Agent、独立观点与可验证工作，也不会诱导用户认为 Agent 越多越好。

升级目标 Slogan 前仍应对至少 10 名英语母语目标用户和至少 10 名中国目标用户做 5 秒理解与复述测试，确认 `verify` 能被理解为 Evidence 与人类验收，而不是 Meldwork 自动保证正确。同一发布页面只使用一套主 Slogan。

### 第二层：品类描述

> **An open, local-first work system for agents across vendors.**
>
> **面向跨厂商 Agent 的开放、本地优先工作系统。**

作用：第一次看见产品的人能够立即理解是什么。

### 第三层：价值主张

> **Bring local and cloud agents into one accountable workspace.**
>
> **让本地与云端 Agent 在一个可追溯、可验收的工作空间内协作。**

作用：解释为什么值得使用。

### MVP 阶段的事实版文案

当前还没有 Cloud Agent、Task、Artifact、Evidence 和团队治理，因此 README 应使用：

> Bring the local Agent CLIs already on your machine into one persistent workspace.

愿景文案与当前能力文案必须分开。

## 4. Logo V2：Open Stitch

### 核心概念

Open Stitch 的主线由一条连续 SVG 路径构成，另以独立端点圆形标记验证状态；整体非对称、连续、开放，并隐约形成小写 `m`。

- 左侧较高：工作从一个明确输入开始。
- 中间回落与再次上升：不同 Agent 接手、修订、挑战。
- 右侧不闭合：系统保持开放，可继续连接新的 Agent 与 Channel。
- 珊瑚色端点：Evidence 被检查、结果被人类验收，或工作进入下一次明确交接的验证点。

它不画“多个 Agent 本体”，而画它们共同作用后的工作连续性。

### 与 Slogan 的关系

> Different agents = 工作线中发生的独立尝试、接手、挑战与修订。
>
> Work you can verify = 产品保留 Artifact、Evidence、测试和人类验收，而不是要求答案一致。
>
> Coral endpoint = 当前结果的验证或明确交接点，不代表所有 Agent 达成共识。

Open Stitch 只负责表达工作连续性、开放接续和结果端点；Evidence、并排比较和审查循环由产品界面与传播演示承担，不向一个简单标志塞入全部功能含义。

### 颜色系统

| Token | 色值 | 用途 |
| --- | --- | --- |
| Ink | `#15171A` | 浅色背景主标志与正文 |
| Paper | `#FFFFFF` | 深色背景主标志 |
| Coral | `#EF5A45` | 端点、验收和少量关键状态 |
| Carbon | `#0E0F11` | App Icon 背景 |
| Mist | `#F4F5F7` | 中性界面背景，不属于标志本体 |

不再使用高饱和品牌蓝作为主标志颜色。黑/白标志能够更自然地适配明暗主题，珊瑚端点提供识别度，但不主导整个 UI。调整后的 Coral 对白色和 Mist 均达到约 3:1 的非文本图形对比度目标。

### 使用规则

- 左侧导航：透明背景，浅色主题用 Ink，深色主题用 Paper。
- App Icon：Carbon 实底、Paper 线条、Coral 端点。
- README / 文档：使用 `<picture>` 或等价主题切换，浅色背景用透明 Ink，深色背景用透明 Paper；不要在 GitHub 深色主题中固定使用 Ink。
- 最小尺寸：标准标志盒高不低于 24px；20px 只用于经过真实像素检查的紧凑导航场景，不再宣称非对称细节在更小尺寸仍完整可读。
- 安全空间：至少为线宽的 1.5 倍。
- 只在中性浅色或深色背景使用；珊瑚色背景会削弱端点识别。
- 禁止拉伸、加阴影、加渐变、加外框或改成对称结构。
- 珊瑚色只用于端点，不把整条线改成彩色。

## 5. 字标

- 字标使用中性、现代、非几何炫技的 Sans Serif。
- 推荐系统栈：Inter / SF Pro / Arial / PingFang SC。
- `Meldwork` 保持正常大小写，不使用全大写。
- 字重建议 620-680；字距为 0，不使用负字距。
- 标志与字标之间保留约一个主线宽度的 2.2-2.6 倍。
- 对外 SVG 字标使用固定轮廓路径，不保留依赖系统字体的 `<text>`，避免 macOS、Windows 和 GitHub 渲染时字宽与重量漂移。
- 对外同时提供 Ink 与 Paper 两个固定轮廓字标；品牌概念板中的说明文字不是生产字标。

首次触达不能只放独立 `m` 标志。README、发布页和商店页面至少同时出现品牌名、Slogan 或品类描述中的两项，避免被理解为普通字母 Logo 或状态通知点。

## 6. 品牌语气

### 应该这样说

- Bring the agents you already use.
- Keep orchestration and work state local.
- Compare independent attempts.
- Review evidence before accepting a result.
- Local control. Explicit provider traffic.

### 不应该这样说

- Build your unstoppable AI workforce.
- Fully private and offline by default.
- Ten agents are always better than one.
- Autonomous swarms that finish everything.
- Enterprise-grade security（在相应审计和能力完成前）。

## 7. PR 主叙事

### Headline

> **Introducing Meldwork: one local workspace for the Agent CLIs you already use.**

许可证提交后才可以使用：

> **Introducing Meldwork: open-source, local-first work for agents across vendors.**

目标产品首屏支持语（Task / Artifact / Evidence / Acceptance 闭环交付并通过理解测试后使用）：

> **Different agents. Work you can verify.**

### Story

1. 开发者已经在多个 Agent 之间工作，但 Session、上下文和权限彼此割裂。
2. Meldwork 让现有本地 CLI 进入一个持续工作空间。
3. MVP 保留原生 Session，并在本机管理会话和编排。
4. 下一阶段让结果从消息升级为 Task、Artifact、Evidence 和 Acceptance。
5. 产品不声称 Provider 流量完全离线，也不强迫用户使用新的云账号。

### Demo 原则

当前 MVP 发布演示只展示真实已实现的本地 Agent 发现、持续会话、同一工作目录和有界讨论。下一阶段原型可以明确标注为：

> 独立方案 → 交叉审查 → 修订 → Evidence → 人类接受

不要演示十个 Agent 头像按顺序发表相似意见。
