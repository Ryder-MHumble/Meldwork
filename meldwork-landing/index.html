What is Meldwork?

THE WORK CELL

Four steps from task to adopted result.

01

Select

Choose the local Agents and participants. Participants are always selected by you — never auto-assigned from a roster.

02

Scope

Bound the goal, working directory, context, and permissions. Every run starts from a frozen task snapshot.

03

Run

Direct, Concurrent Responses, or Auto Discussion V4 — from a single focused session to negotiated multi-round work.

04

Review & adopt

Inspect findings, evidence, and any Human Gate before the workspace changes. Nothing writes itself.

COLLABORATION MODES

Same Case, same evidence trail — different depth of agreement. Pick the mode that matches how much review the decision deserves.

HOW MELDWORK DIFFERS

An organization layer, not another runner.

Meldwork connects the local Agent tools you already use to a decision-ready review workflow — and keeps independent findings, evidence, responsibility, and the human adoption decision visible in one local work cell.

  • Finding → Evidence → Decision → Disposition

    Dissent stays visible. Disagreement, re-checks, and adoption records are tracked — never hidden behind a central manager.

  • Human Gate before workspace writes

    Workspace writes are opt-in workflow controls. You adopt the result — the agents don't.

  • Local-first boundaries

    Runs in your Electron work cell with existing CLIs. No cloud Agent fleet, no required server, conversations stay local.

  • Frozen context, independent judgment

    Case-scoped independent judgments with evidence-backed decisions — not terminal count or worktree throughput.

THE BOUNDARY

What Meldwork is, and isn't.

Is

  • A local-first Electron app for desktop review workflows.
  • A work cell that orchestrates the Agent CLIs you already have.
  • An evidence-first review record (Finding → Evidence → Decision → Disposition).
  • Workspace writes as opt-in workflow controls.
  • Source-available under the Meldwork Non-Commercial Source License 1.0.

Isn't

  • Not a hosted Agent fleet or general Agent framework.
  • Not automatic participant selection from a larger roster.
  • Not enterprise SSO / RBAC / governance tooling.
  • Not an operating-system sandbox — writes happen through your shell.
  • Not fully offline — a selected Agent may send prompts to its configured Provider.

ANSWERS

Questions teams ask before adopting.

Short, honest answers — the long versions live in architecture.md ↗.

  • Meldwork is a local-first work cell for AI coding agents. It orchestrates the agent CLIs you already run — Codex, Claude Code, Gemini CLI, and 9 more — around one frozen task snapshot, records every finding as evidence, and puts a human adoption gate before any workspace change.

  • No, not by itself. Meldwork runs locally in your Electron work cell. Selected Agents send prompts, attachments, or Skills to their own configured Provider — but Meldwork itself is a local review UI, not a cloud relay. Conversations stay on your machine.

  • Twelve today — Codex, Claude Code, Gemini CLI, Qwen Code, Kimi Code, MiMo Code, OpenCode, OpenCodeReview, Hermes, Pi Agent, OpenClaw, and WorkBuddy. Approved Agent Connectors can be added through the Agent Connector SDK; custom executables use the desktop custom-Agent path.

  • A terminal runs one Agent at a time and shows raw output. Meldwork scopes a single task across multiple Agents, captures their independent findings, attaches evidence, and keeps the human adoption decision visible as a first-class artifact.

  • The current V1.0.3 preview targets Apple silicon macOS (ad-hoc signed, not notarized — open Open Anyway in System Settings → Privacy & Security on first launch). Cross-platform builds are on the roadmap; the app is Electron so the same source compiles everywhere once those targets land.
